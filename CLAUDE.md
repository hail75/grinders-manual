# Grinder’s Manual Trainer: context for Claude Code

A mobile-first study companion for *The Grinder’s Manual* (Peter Clarke, 6-max NLHE, 100bb): 14 chapter lessons with quizzes, a trainer (pre-flop chart spots and post-flop spots generated by code) on a poker table, math drills. (The flashcard Review section was removed in v2.3 at the owner's request; old saves may still hold a `cards` field, which is ignored.) Sister app of `hail75/holdem-drill`: same table and card design and fonts (Fraunces + Instrument Sans), but its own palette, **Midnight & Brass** (the owner chose it from four in v2.2; there is no palette picker).

## Files
- `index.html`: the whole app (HTML, CSS, JS in one file, no build step, no dependencies).
- `manifest.webmanifest`, `sw.js`, `icon-*.png`, `apple-touch-icon.png`: installable PWA with offline support. **Every release: bump `CACHE` in `sw.js` (`grinders-manual-X.Y.Z`) and `BUILD.v` in `index.html` together, and set `BUILD.at` to the release time in UTC (`"2026-11-19T10:15Z"`).** Small fix bumps Z, new feature bumps Y, big change bumps X. Settings shows the version and build time, so you can tell when a deploy has loaded.
- `icon.svg`: the one source for the logo (header and rail inline the same markup). PNGs are rendered from it with Playwright: 192 and 512 with transparent rounded corners, apple-touch (180) and maskable (512, mark scaled to 78%) without corners.
- `fonts/`: bundled web fonts, cached by `sw.js`. Nothing loads from Google Fonts.
- `docs/`: README screenshots. Retake them after a visible UI change.
- `tests/verify.mjs`: **run `node tests/verify.mjs` after every change; it must print "All checks passed".**
- Hosted on GitHub Pages from `main`, repo root.

## Code map (inside `index.html`)
Everything above `/* ===================== UI` is data and pure functions; the tests load it in Node, so keep DOM code below the marker.
1. `RANGES` (opens by seat), `CALLS` (flat tiers), `MODES` (the original Ch. 2/6 spots: `grp`, `seat`, `vill`, `act`, `set`, `info`), `XMODES` (26 more spots read cell by cell from the book's figures, `fig` = figure number: `opts` answers `[key,label]`, `tiers` `[key,css,legend,hands]`, `scene` chips/actions on the table, `pool` = only these hands are dealt, `base`+`add`/`drop` for the dynamic opening charts), merged into `MODES` and normalised so every spot has `opts`, `tiers`, `ans` (hand → answer key, anything else folds) and `set`. Groups: Open, Flat, BB defend, 3-bet, vs 3-bet. Flat and BB defend (v2.12, owner's request) answer 3-bet / Call / Fold: Ch. 6's calling chart with Ch. 10's value 3-bets as the first tier, [QQ+ AK] (the book's "common tight 3-bet value model"), or Figure 54's value hands for BB vs BU 2x; bluff 3-bets stay in the 3-bet group because they need reads (`value3`, tests check it). `rangePct`, `answerOf`, `tierOf`. The book's charts were extracted from the PDF by reading each cell's colour; the tests check the combo counts the book prints. Don't type ranges by hand.
2. `LESSONS`: `{id, ch, title, mins, sum, tool?, blocks:[[heading, html]], quiz:[[q, options, answerIndex, why]]}`. Helpers `P` (HUD stat pill), `GB` (good/bad factor table), `KEYBOX`. Lesson text reads range sizes from the data (`rangePct`), not typed numbers.
3. `toolHTML`/`bindTool`: the interactive lesson tools. `MATH`: drill generators returning `{q, opts, a, why}`.
3b. Post-flop spots (`/* ---------- post-flop spots`, v2.11): `PMODES` (`cb-ip`, `cb-oop`, `cb-mw` in group C-bet; `vb-turn`, `vb-river` in group Value bet), each with `gen()` returning a plain-JSON spot `{kind, seat, vill, hole, board, pot, info, hud, opts:[key,label,amount], ans, verdict, why, notes{key:why-not}, principle, factors|q}`. Cards are `'Td'` strings. `pfScore` (evaluator), `pfRead` (made-hand class: strong/over/top/mid/low/under/none), `pfTexture` (Ch. 4's types 1-5; the tests check the lesson's ten example flops), `pfOuts` (the Ch. 4 outs table; tests check the book's KJ/AQ/77 examples). `PF_TYPES` are the book's player types (Reg, Nit, Fit-or-fold Fish, Station Fish, Aggro Fish) with HUD ranges. C-bets: `cbGrade` = value → bet; stable SDV → check; light hands → expected folds (`cbFold`: his Fold to F Cbet moved by texture, range, position, raise stat; multiplied multiway) vs needed (RFE of the size minus equity), dealt only when the margin is 8+ points either way; size `cbSize` = the lesson's sizing grid vs aware players (flop dry 1-2 / semi-wet 3 / wet 4-5 = 0/1/2, plus range BU 0, CO/SB 1, UTG/HJ 2; 0-1 small ½, 2 medium ⅔, 3-4 large pot; the Ch. 4 lesson shows the same grid), big value / small light vs Fish. Value bets: `vbGrade` = the Ch. 5 flowchart (Q1 relative strength with scare cards and opponent type, Q2 stack vs pot, Q3 slowplay only with a short stack), size by elasticity (Fish inelastic → pot, Reg → ⅔, thin vs Reg → ½, all-in when the stack is under a pot). Unclear spots return null and aren't dealt. Change a rule → update the explanation text and the tests together.
3c. Spaced repetition (`LADDER`, `revAdd`, `revAnswer`, `revDue`): a missed trainer spot (pre-flop `{h,u}` or the whole post-flop spot) is saved in `S.rev` and comes back in the topic being drilled 3-4 spots later, ~15 later, then 1, 3, 7 days; `REV_GAP` keeps it to one spot in four. `S.rvN` counts spots dealt.
4. UI: hash routes `#home`, `#lesson-<id>`, `#ranges[/<mode>|/mix-<group>|/mix-All]` (the Trainer tab, Practice view; `SPOTS` = `MODES` + `PMODES`; `mix-All` deals from every topic or the ones ticked in `S.mixG`, picking a topic first so post-flop isn't swamped by the 42 chart spots), `#charts[/<mode>]` (Trainer, Charts view: browse any chart without dealing, tap a square for its answer, `CH`, `renderCharts`; Practice/Charts switch is `tabsHTML`; v2.14 replaced the two sideways-scrolling topic rows with one bar, `pickBarHTML`, that opens `openPicker(view)`: a sheet listing every group as an accordion with Mix rows, the all-topics mix toggles, and per-spot accuracy and due reviews), `#math`, `#progress`, `#settings`. `render()` per view. The range trainer draws the table with `tableHTML` (seats on an oval, hero at the bottom, chips `.stk` between seat and pot, dealer button on BU) and the chart with `gridHTML`.
5. Storage: localStorage key `gm-trainer-v1`, state `{lessons, quiz, drills, days, math, log, rev, rvN, mixG, theme}`. Keep the key and shape; add fields with defaults in `BLANK()`.

## Conventions
- Phone first: tap targets at least 44px, the main action in the sticky `.actions` bar above the bottom nav. At 960px and up the nav becomes a left rail and drills go two columns.
- Every colour is a CSS variable with light and dark values (`:root`, the dark media query, and `[data-theme="dark"]`). Check both themes and both widths after a visual change.
- Colour roles: `--felt*` is the navy primary (table, primary buttons, hero card; the name is historical), `--gold` the brass accent, `--accent` links and the active tab. Right and wrong use only `--good*` and `--bad*` (teal-green, brick-red, with `-mark` for the ✓/✗ circles); never colour a right answer with the primary.
- Touch feedback: `.press` is added on `pointerdown` (touch browsers apply `:active` late), the picked answer pops or shakes, and right/wrong options get ✓/✗ marks. Touch screens hide the 1–4 key badges and the keyboard help (`.kbd-only`). No vibration (the owner asked for visual feedback only).
- Chart colours (v2.11 made them consistent, v2.13.1 made tiers distinct after the owner found the teal shades unreadable and missed the gold dynamic hands): each colour means one thing in every chart, set in the MODES normalisation from the option label and tier legend. Raise: navy `in` = value / default open, violet `in2` = light raise (3-bet bluff, raise-then-fold), gold `dy` = opens only at this table (dynamic). Call: teal `cl`, orange `cl2`, rose `cl3` for the wider call tiers. Grey = fold, gold stripes `dyn` = a default open you fold here. Tests enforce it.
- Seat labels (v2.11.1, owner asked for consistency): every table, pre-flop and post-flop, labels a seat with `seatLines(type, action)`: the player type on one line when the spot names one (`WHO` map for the chart spots, `PF_TYPES.short` for post-flop: Reg, Nit, Fish, Station, Aggro, Fish/Nit, 3-bettor, 40bb), what the seat did on the next (Raise 3, Call 3, 3-bet 8, Check, Fold). A test fails if a spot's info names a player type the table doesn't show.
- Cards show **10**; labels and charts use **T**. Suits are two-colour (red hearts and diamonds).
- Before adding a CSS class, search the file for the name. v2.0.1 reused `mid` (the table’s pot-centring class) for a 5/6 quiz result and for 75–90% progress bars, and both floated over the page as absolute boxes (holdem-drill had the same bug with `chips`). The tests now fail if a class with its own rule is also used as a modifier.
- Keyboard: 1–4 answer, Enter next, ← → lesson pages, R / C / F in the range trainer (first answer, call, fold).
- Lessons follow the book chapter by chapter, part by part (Ch. 4 rebuilt in v2.7, Ch. 5-14 in v2.8-v2.10 after an audit against the book): each book section has a part, with the book's worked numbers and examples, and each chapter has 9-15 quiz questions. Keep that standard when editing: read the book's section first. Lessons can draw example flops with `FL('K♣ 7♦ 2♥')` and place their tool on a named part with `toolAt`. The page heading (top left) is Instrument Sans bold (owner's choice); Fraunces stays for lesson titles, numbers and cards.
- Lesson text is a summary in our own words; do not paste text from the book.
